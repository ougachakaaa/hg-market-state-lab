## Evidence and reproducibility

Each formal real-market Example has a versioned manifest associating these records with
the complete producer result. Field spelling does not create a competing business schema.

| Required record | Meaning |
| --- | --- |
| Actual Source Provenance | Actual upstream origin and acquisition route, linked to retained input evidence; no inferred authenticity from labels |
| Provider / Dataset Identity | Actual provider, dataset/product identity and relevant source revision; record each dependency separately |
| Acquisition Timestamp | Actual acquisition time with timezone, distinct from market observation and generation time |
| Requested Window | Fixed inclusive request or single-day observation and price type from the Example contract |
| Observed Coverage | Actual observed sessions/range, gaps and formal producer coverage outcomes; never substituted request endpoints |
| Input Fingerprint | Digest/identity of the exact retained inputs, including separately declared out-of-window preparation dependencies |
| Formal Producer Identity | Owning public entry, code revision, invocation, parameters and execution/toolchain evidence |
| Result Profile / Definition Version | Published result profile, strategy/report definition and relevant projection versions |
| Result Digest | Content digest of the packaged result associated with the input and producer records |
| Public Disclosure | Human-readable historical source, observation/window, actual coverage, producer and limitations; no live execution or actual trading claim |
| Publication Rights Status | Source/output/channel-specific review, basis, conditions and unresolved restrictions; independent of authenticity and integrity |

Retain exact legal inputs privately for offline verification/replay with recorded versions.
Digests establish integrity and association, not market authenticity or redistribution
permission. Reacquisition is explicit and may differ from the retained snapshot. Offline
verification needs no credentials/network; release consumes committed cleared results only.
Private evidence may retain necessary acquisition details; public disclosure must redact
credentials, private paths and sensitive metadata without hiding the actual market origin.

## Independent gates

Each gate records PASS / FAIL / BLOCKED, reviewed object/version, evidence reference,
reason, reviewer and review time. PASS requires evidence; proven violation is FAIL;
unresolved dependency, access or evidence is BLOCKED. UNKNOWN rights remain BLOCKED,
never default PASS. Do not collapse these gates into a single contract-validation badge.

| Gate | PASS evidence |
| --- | --- |
| Real Source Gate | Genuine historical inputs traced to actual provider/dataset and acquisition evidence; no synthetic substitution |
| Formal Producer Gate | Unchanged formal public producer path, version and execution evidence; no handwritten financial output |
| Contract / Identity Gate | Formal schemas/profiles, request/result agreement, references, Views and digests validate |
| Coverage Gate | Target day/window verified against formal calendar/scope, actual missing sessions and preparation dependencies; no invented completeness |
| Publication Rights Gate | Documented permission covering the exact output, distribution channel and intended public uses |
| Public Data Safety Gate | Reviewed actual public files contain no secrets, private paths, sensitive metadata or uncleared source/derived data |

A legal producer partial/empty result retains its scientific status. Coverage review records
that status and any unmet Example requirement; it does not rewrite producer completeness.
Unavailable target-day inputs cannot be replaced by a different date. Known inability is
FAIL; unresolved feasibility is BLOCKED with a specific reason.

## Development First and public admission

Publication Rights review is not a prerequisite for lawful acquisition, local research,
result generation, private storage or local UI integration. D3-R1-R6 local development and
technical acceptance continue while that gate is BLOCKED. Acquisition still requires legal
access and compliance with provider use terms. Technical acceptance requires the first four
gates PASS; diagnostic work can continue while technical gaps are explicitly unresolved.

Private Evidence and uncleared local static assets must live outside Git tracking and
public build/deployment paths. Before generation, choose a private location and verify its
isolation; do not add real restricted inputs or results to tracked test fixtures, public
assets, shared CI artifacts, logs or deployment packages. A private local static build may
consume these assets without creating a second Presentation or runtime business model.

An independent Publication Review checks the exact intended repository additions and
GitHub Pages artifact, including downloaded/exported content and reachable assets. All six
gates must PASS before public inclusion. Local technical PASS with public BLOCKED is a
valid separate outcome, including at R6. Existing V1 publishing is unchanged by R0.

Access to quotations and permission to redistribute quotations or derived results are
separate rights. Attribution alone does not authorize complete Tushare datasets. Do not
perturb values, conceal sources or mislabel real inputs Synthetic to bypass review. Do not
assume aggregate statistics, charts, reports, metadata or downloads are automatically exempt.
