# Private seven-page static build contract

Specializes [Demo Runtime](ARCHITECTURE.md), [Examples](EXAMPLES.md) and
[authenticity](AUTHENTICITY.md). This concern owns private admission and build
isolation; feature owners retain all result schemas and rendering.

## Admission and output

The explicit `demo:build:private` command requires absolute external R2, R3 and
WP-A package roots and an absolute external, new output directory. Resolve symlinks
and reject every repository/worktree location, overlaps and repository symlink
aliases. No environment variable selects private inputs. Default `demo:build`,
`dist-demo` and Pages upload are unchanged. No private data enters CI inputs.

Admission first runs the existing credential-free R2 verifier, R3 Verify/Replay
and WP-A verifier (including formal W2 reproduction and Publication Reader checks).
It checks sealed inventories, origin, producer, fixed request, complete identity,
coverage and all six feature validators. WP-A references must match the explicitly
selected R2/R3 packages. Any failure stops before building; no acquisition,
synthetic fallback or financial producer run is available. Formal offline replay
is verification of retained evidence, separate from the static bundling phase.

Only complete Chain/Premium projections, the R3 reader report, the safe Python
Publication Reader export, genuine Catalog and both complete W2 Results enter a
virtual Vite module. Raw captures, Dataset caches, Publication source evidence and
private root paths never enter this module. No second financial DTO is introduced.
The browser validates a versioned presentation envelope with exact Example
identities, real-market provenance, private rights, SHA-256 and feature contracts
before mounting any business page. An invalid envelope yields an explicit static
error and no previous result or HTTP fallback. Digests establish retained integrity,
not independent market authentication or redistribution rights.

## Composition and origin

One static composition mounts ApplicationShell, AppUiProvider, workspaceRoutes,
useHashRoute and the six formal Feature Presentations plus DailyDataLanding.
The default is `#/research`. No production controller, Auth, HTTP client, Submit,
Preflight, polling or Provider dependency is permitted in the static module graph.
Build-time graph inspection fails closed and emits an external dependency receipt.
After SSR admission, the bundler explicitly selects production JSX and scans every
emitted asset for repository/private/source paths before writing a PASS receipt.

Delivery (static), source (real market), execution (historical embedded formal
result) and publication rights (private / public BLOCKED) remain separate metadata.
Validated Example records drive disclosure, including report Evidence, backtest
Evidence, Copy/Export and Premium Inspector. Optional presentation disclosure
propagation preserves historical Synthetic defaults and production wording. UI
metadata is never added to formal business DTOs or exported business payloads.
Local strategy selection switches only the two validated W2 Results. All other
local feature interactions keep their existing semantics.

Initial acceptance and commands are recorded in [WP-B acceptance](WP_B_ACCEPTANCE.md);
current dependency/CI and private reproduction evidence is [D7 readiness](D7_READINESS.md).
Publication Rights remain BLOCKED; this contract grants no public release.

## Continuous compatibility (WP-C)

Private composition owns a typed route-to-Presentation mapping whose keys must
exactly cover `workspaceRoutes`. CI type-checks it and builds the actual private
entry with an empty, explicitly test-only virtual envelope solely to inspect the
module graph. This artifact cannot pass admission and is discarded; it is never
a V2 Example or browser acceptance substitute. Real private verification and browser
acceptance remain explicit external-input operations. Public safety additionally
scans tracked payloads/credential literals and the actual default V1 output; Pages
continues to upload only `ui_web/dist-demo` without private command references.

Startup visibly reports static admission loading while WebCrypto and validators run;
only successful admission mounts business pages. Browser acceptance holds that actual
admission promise to verify loading, then releases it without arbitrary sleeps.
